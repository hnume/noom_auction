# User Onboarding Flow — Plan (Draft)

> สถานะ: **Draft** — ใช้คุยกับทีมก่อนลงมือทำ
> ขอบเขต: ลงทะเบียนผู้ใช้ใหม่ 4 ขั้น จบที่ผล Credit Score และการยืนยัน

---

## 1. ภาพรวม Flow

```
[Step 1] ข้อมูลยืนยันตัวตน  →  [Step 2] ข้อมูลอาชีพและรายได้  →  [Step 3] คำนวณ Credit Score  →  [Step 4] แสดงผลและยืนยัน
  เลขบัตรประชาชน                  อาชีพ                               (ระบบทำ, ผู้ใช้รอ)                   คะแนน + ระดับ
  เบอร์โทรศัพท์                   รายได้ต่อปี                                                              ปุ่มยืนยัน / แก้ไข
                                  ประสบการณ์ทำงาน (ปี)
```

- ผู้ใช้ย้อนกลับไปแก้ Step 1–2 ได้ทุกเมื่อก่อนกดยืนยันใน Step 4
- ถ้าแก้ข้อมูล Step 2 ต้องคำนวณ Step 3 ใหม่ทุกครั้ง
- มี progress bar แสดง "ขั้นที่ X จาก 4" ทุกหน้า

---

## 2. รายละเอียดแต่ละขั้น

### Step 1 — เลขบัตรประชาชน และ เบอร์โทรศัพท์

| ฟิลด์ | ชนิด | กติกา (Validation) |
|---|---|---|
| `national_id` | string 13 หลัก | ตัวเลขล้วน 13 หลัก + ผ่าน checksum บัตรประชาชนไทย (ดูข้อ 5.1) / ห้ามซ้ำกับผู้ใช้ที่มีอยู่ |
| `phone` | string 10 หลัก | ขึ้นต้นด้วย `06`, `08`, `09` / ตัวเลขล้วน 10 หลัก |
| `consent_pdpa` | boolean | ต้องติ๊กยอมรับก่อนไปต่อ (เก็บเวลาที่ยินยอมด้วย) |

- UI: ใส่ขีดคั่นอัตโนมัติตอนพิมพ์ (`1-2345-67890-12-3`, `081-234-5678`) แต่เก็บลง DB เป็นตัวเลขล้วน
- (เผื่ออนาคต) ยืนยันเบอร์ด้วย OTP — **ยังไม่อยู่ในขอบเขตรอบนี้**

### Step 2 — อาชีพ, รายได้ต่อปี, ประสบการณ์ทำงาน

| ฟิลด์ | ชนิด | กติกา |
|---|---|---|
| `occupation` | enum (dropdown) | ต้องเลือก 1 ค่า จากรายการในข้อ 5.2 |
| `annual_income` | integer (บาท) | ≥ 0 และ ≤ [เพดานที่ทีมกำหนด] / ใส่ comma ตอนแสดงผล |
| `years_of_experience` | integer (ปี) | 0–50 |

- ห้ามให้พิมพ์อาชีพอิสระเป็นข้อความ (ใช้ enum เพื่อให้คำนวณคะแนนได้)

### Step 3 — คำนวณ Credit Score

- ทำฝั่ง **server** เท่านั้น (ห้ามคำนวณบน client เพื่อป้องกันการแก้ค่า)
- หน้าจอแสดง loading "กำลังประเมินคะแนน…" ระหว่างรอ
- เก็บผลลง DB พร้อม `scoring_version` เพื่อรู้ว่าคำนวณด้วยสูตรเวอร์ชันไหน
- สูตรตั้งต้นดูข้อ 5.3 (**ตัวอย่าง ต้องให้ทีม/ฝ่ายธุรกิจยืนยันน้ำหนักก่อน**)

### Step 4 — แสดงผลและยืนยัน

แสดง:
- คะแนนรวม (เช่น 0–100) และระดับ (A / B / C / D)
- สรุปข้อมูลที่กรอก (เลขบัตรแสดงแบบปิดบัง `1-XXXX-XXXXX-12-3`, เบอร์ `081-XXX-5678`)
- คำอธิบายสั้นๆ ว่าคะแนนมาจากอะไร (อาชีพ / รายได้ / ประสบการณ์)

ปุ่ม:
- **ยืนยัน** → บันทึกสถานะ `confirmed`, สร้างบัญชีสมบูรณ์, ไปหน้าหลัก
- **แก้ไขข้อมูล** → กลับ Step 1 หรือ 2 (ข้อมูลเดิมยังอยู่)

## 4. API (ร่าง)

| Method | Path | ทำอะไร |
|---|---|---|
| POST | `/onboarding` | เริ่มใบสมัคร (status = draft) |
| PATCH | `/onboarding/:id/identity` | บันทึก Step 1 |
| PATCH | `/onboarding/:id/profile` | บันทึก Step 2 (ล้าง score เก่า) |
| POST | `/onboarding/:id/score` | คำนวณ Step 3 → status = scored |
| GET | `/onboarding/:id` | ดึงข้อมูล + ผล (Step 4) |
| POST | `/onboarding/:id/confirm` | ยืนยัน → status = confirmed |

- ทุก endpoint ต้องเช็คว่า `user_id` เป็นเจ้าของใบสมัคร (authorization)
- `confirm` ได้เฉพาะตอน status = `scored`

## 5. กติกาเพิ่มเติม

### 5.1 Checksum บัตรประชาชนไทย
1. เอาตัวเลข 12 หลักแรก คูณด้วยน้ำหนัก 13, 12, 11, … , 2 ตามลำดับ แล้วรวมกัน
2. `check = (11 - (sum mod 11)) mod 10`
3. `check` ต้องเท่ากับหลักที่ 13

### 5.2 รายการอาชีพ (ร่าง — ให้ทีมเติม/ตัด)
- พนักงานรัฐ / รัฐวิสาหกิจ
- พนักงานบริษัทเอกชน
- เจ้าของกิจการ
- อาชีพอิสระ / ฟรีแลนซ์
- นักศึกษา
- อื่นๆ

### 5.3 สูตร Credit Score ตั้งต้น (v1 — ตัวอย่าง)
คะแนนเต็ม 100 = อาชีพ 30 + รายได้ 40 + ประสบการณ์ 30

| ปัจจัย | เกณฑ์ (ตัวอย่าง) | คะแนน |
|---|---|---|
| อาชีพ | รัฐ/รัฐวิสาหกิจ 30, เอกชน 25, เจ้าของกิจการ 20, ฟรีแลนซ์ 15, นักศึกษา 5, อื่นๆ 10 | 0–30 |
| รายได้ต่อปี | แบ่งช่วงรายได้ [ช่วงที่ทีมกำหนด] ไล่คะแนน 0–40 | 0–40 |
| ประสบการณ์ | `min(ปี, 10) × 3` | 0–30 |

ระดับ: A ≥ 80, B 60–79, C 40–59, D < 40 (ตัวอย่าง)

> สูตรแยกเป็น class/service เดียว (`CreditScorer`) มี `VERSION` เพื่อเปลี่ยนสูตรได้โดยไม่กระทบข้อมูลเก่า

## 6. Edge Cases

- เลขบัตรซ้ำกับผู้ใช้อื่น → แจ้ง "เลขบัตรนี้ถูกใช้ลงทะเบียนแล้ว" (ไม่บอกว่าเป็นของใคร)
- ปิดหน้าเว็บกลางคัน → กลับมาทำต่อที่ `current_step`
- แก้ Step 2 หลังได้คะแนนแล้ว → ล้างคะแนน, status กลับเป็น `draft`, ต้องคำนวณใหม่
- คำนวณคะแนนล้มเหลว → แสดงข้อความ + ปุ่ม "ลองอีกครั้ง"
- กดยืนยันซ้ำ (double click) → ทำครั้งเดียว (idempotent)

## 7. Acceptance Criteria

- [ ] กรอกเลขบัตรผิด checksum → ไปต่อไม่ได้ และเห็นข้อความผิดพลาดใต้ช่อง
- [ ] กรอกเบอร์ไม่ใช่ 06/08/09 หรือไม่ครบ 10 หลัก → ไปต่อไม่ได้
- [ ] ไม่ติ๊ก PDPA → ปุ่มถัดไปกดไม่ได้
- [ ] Step 2 ทุกช่องบังคับกรอก และตรวจช่วงตัวเลข
- [ ] คะแนนคำนวณบน server และตรงกับสูตร v1 (มี unit test ทุกช่วงคะแนน)
- [ ] Step 4 แสดงเลขบัตร/เบอร์แบบปิดบัง
- [ ] กดยืนยันแล้ว status = `confirmed` และกลับมาแก้ไม่ได้
- [ ] ผู้ใช้ A เปิดใบสมัครของผู้ใช้ B ไม่ได้
